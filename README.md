# 추천 균형 연구실

추천 균형 연구실은 초등학교 6학년 학습자가 교실에서 약 35분 동안 사용하는 결정적 추천 모형입니다. 주제는 과학·예술·스포츠·자연·역사이며, 목표는 실제 서비스의 성능을 평가하는 것이 아니라 선택 기록, 추천 분포, 공급 조건이 결과에 어떤 차이를 만드는지 설명하는 것입니다.

## 수업 목표와 핵심 개념

교육과정 연결은 6실05-04(데이터의 유형과 활용 데이터 탐색), 6실05-05(인공지능 과정과 사회 영향 탐색), 디지털 시민성(책임 있는 선택과 다양한 관점 존중)입니다. 학습자는 반복 선택이 자료로 남는 방식, 관련성 증가와 다양성 감소의 동시 발생, 균형 설정의 절충, 모형의 한계를 기록합니다.

선택 편향은 학습자가 같은 주제를 반복해서 선택한 기록에서 생기는 한쪽 방향의 자료입니다. 분포 피드백 고리는 그 기록이 다음 추천의 주제 비율에 영향을 주고, 바뀐 목록이 다시 선택 기회에 영향을 주는 흐름입니다. 이 모형에서는 다양성 설정과 콘텐츠 공급 조건도 함께 결과를 바꿉니다.

## 다섯 미션

1. **선택의 흔적** — 같은 주제 카드를 세 번 고르고 다음 목록을 예측합니다.
2. **좁아진 창** — 초기 목록과 변화한 목록의 주제 수를 비교합니다.
3. **탐색 버튼** — 포커스가 아닌 낯선 주제 카드 한 장을 의도적으로 엽니다.
4. **균형 조정** — 다양성·관심 기록 설정을 바꾸어 세 목록을 비교합니다.
5. **모델 감사** — 같은 선택이어도 공급 목록이 다르면 결과가 어떻게 달라지는지 확인합니다.

## 모형의 정확한 규칙

- 피드는 항상 8장입니다. 각 주제의 토큰은 `기본 토큰 + 관심 토큰 × 2 + 다양성 토큰`입니다. 관심 기록을 비우면 관심 토큰은 0이 됩니다.
- 8장의 주제 수는 토큰 비율의 largest-remainder 방식으로 배분하며 공급 용량을 넘지 않습니다. 소수점 나머지가 같으면 주제 순서 과학 → 예술 → 스포츠 → 자연 → 역사 순으로 먼저 배분합니다.
- 같은 입력은 무작위성 없이 같은 결과를 냅니다. 카드 위치는 후보 목록에서 `(round × 2 + topicIndex) % topicCandidateCount`부터 후보 순서대로 선택합니다.
- **균형 공급**은 다섯 주제의 기본 토큰이 각각 1이고 전체 카드 후보를 사용합니다. **자연 풍부 공급**은 자연 기본 토큰이 4, 나머지가 1이며 자연 카드는 모두, 다른 주제는 앞의 5장 후보를 사용합니다.

각 카드의 “왜 이 카드가 나왔나요?” 설명에는 기본·관심·가중 관심·다양성·전체 토큰, 배정 카드 수, 공급 프로필, 결정적 위치 규칙이 표시됩니다. 설명은 계산 근거를 보여 주지만 실제 추천 시스템의 내부 동작을 뜻하지 않습니다.

균형 조정에는 모두에게 맞는 단일 최적 설정이 없습니다. 학습자는 새로운 주제 탐색 또는 익숙한 주제 심화 목적을 고르고 세 개의 스냅샷을 비교한 뒤, 목적에 맞는 선택과 그 절충을 근거와 함께 보고합니다.

## 한계와 개인정보 경계

이 앱은 가상의 단순 규칙이며 실제 서비스 추천을 판정하거나 재현하지 않습니다. 실제 시스템에는 더 많은 자료와 무작위 조건이 작용할 수 있습니다. 실제 취향, 검색 기록, 계정 정보, 쿠키를 수집하거나 전송하지 않으며 선택 기록은 현재 탭의 메모리 안에서만 유지됩니다. 저장소·쿠키·네트워크 API를 사용하지 않고, 순위나 학습자 간 비교를 만들지 않습니다.

## 접근성

학습 행동은 이름 있는 native button, radio, checkbox, slider로 조작할 수 있고 키보드 Enter/Space 경로를 제공합니다. 단계가 바뀌면 단계 제목에 포커스를 돌려 현재 위치를 알립니다. `prefers-reduced-motion`에서는 피드 전환 애니메이션과 pulse 대신 같은 표·문장·“지금 할 차례” 정적 안내를 유지합니다. 카드 이유 dialog는 열릴 때 dialog에 포커스를 주고 Tab/Shift+Tab을 dialog와 닫기 버튼 안에서 순환시키며, 문서 Escape와 닫기 뒤 원래 trigger 포커스 복원을 제공합니다. 업데이트 내역 dialog도 Escape와 닫기 후 trigger 복원을 제공합니다.

이번 요청 범위에는 실제 사람의 macOS VoiceOver 검수가 포함되지 않았습니다. QA 기록은 이를 `범위 제외(사용자 요청)`으로 표시하며, 자동 검사 결과를 사람 검수 통과로 바꾸지 않습니다.

## 로컬 명령

Node `v24.15.0` 환경에서 다음 명령을 사용할 수 있습니다.

```sh
npm run test:scripts
npm run check:lines
npm run check:boundaries
npm run test:run
npm run typecheck
npm run lint
npm run build
npm run quality
```

`npm run quality`는 lint → typecheck → scanner tests → line/boundary checks → Vitest → production build 순서로 실행합니다. 브라우저 E2E는 별도 명령이며, 현재 QA 문서에는 최종 보완 후 `post-fix E2E 미검증` 상태가 정직하게 기록되어 있습니다.

이 저장소의 범위는 로컬 구현과 검증 문서입니다. 배포, 원격 저장소 설정, HVC 등록·갤러리 동기화는 포함하지 않습니다.
